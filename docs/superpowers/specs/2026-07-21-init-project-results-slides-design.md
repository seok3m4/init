# init 프로젝트 결과보고서 17~24페이지 설계

## 커뮤니케이션 목표

발표가 끝날 때 정글·KCCI 프로젝트 평가자는 `init`이 채용 공고 생성부터 지원, AI 면접, 근거 기반 평가와 합격자 선별까지 연결한 실제 동작 가능한 채용 플랫폼이며, 비동기 처리·가드레일·대규모 데이터 검증으로 신뢰성을 확보했다는 점을 이해해야 한다.

## 편집 범위

- Google Slides 원본의 기존 흑백 템플릿, 제목 체계, 여백, 페이지 흐름을 유지한다.
- 17페이지 작성요령은 삭제한다.
- 18~24페이지를 프로젝트 내용으로 교체한다.
- 25~26페이지 멘토링 일지는 수정하지 않는다.
- 기존 1~16페이지와 중복되는 프로젝트 개요보다 구현 결과와 검증 근거를 우선한다.

## 장표 구성

### 18. 전체 구현 프로세스

- 목적: 프로젝트가 기획, 계약, 구현, AI 파이프라인, 검증으로 이어졌음을 한눈에 보여준다.
- 형식: 기존 5열 표 레이아웃을 유지한다.
- 행: 계약·아키텍처 정렬, 기업 채용 흐름, 지원자 면접 흐름, AI 평가 파이프라인, QA·배포 검증.
- 핵심 메시지: 화면 구현에 그치지 않고 API 계약과 상태 전이를 기준으로 전체 흐름을 연결했다.

### 19. 공고부터 리포트까지 하나의 채용 흐름으로 연결

- 목적: 기업과 지원자 양쪽의 end-to-end 사용자 흐름을 설명한다.
- 형식: 좌우 흐름을 가진 간결한 프로세스와 실제 화면 2~3개를 조합한다.
- 흐름: 공고/JD 설정 → 지원서·이력서 제출 → AI 면접 → 비동기 분석 → 평가 리포트·선별.
- 구현 근거: Next.js, NestJS, PostgreSQL/Prisma, S3, SQS/worker.

### 20. JD와 이력서가 질문의 근거가 된다

- 목적: 일반 질문 나열이 아니라 채용 맥락에 맞춘 질문 생성임을 보여준다.
- 형식: 입력, 처리, 결과의 3단 구조와 질문 설정 화면을 사용한다.
- 입력: 공고 JD, NCS 평가 기준, 지원자 이력서.
- 처리: 공통 질문과 개인화 질문 생성, NCS profile 정렬, 가드레일 검증.
- 결과: 세션별 불변 질문 snapshot과 답변 기반 꼬리질문.

### 21. 면접은 실시간으로 진행되고 실패에도 복구된다

- 목적: 지원자 면접 런타임의 핵심 구현을 보여준다.
- 형식: 면접 화면 중심의 큰 이미지와 핵심 기능 4개 이내의 설명을 사용한다.
- 기능: 장치 점검, 영상·음성 답변 저장, STT, 문맥 기반 꼬리질문.
- 안정성: 새로고침 시 미답변 질문 복원, AI 지연·실패 시 상태 기반 복구, 원본 파일은 S3에 저장.

### 22. 평가는 점수보다 근거와 안전성을 먼저 보장한다

- 목적: AI 결과를 바로 확정하지 않는 평가 구조를 설명한다.
- 형식: 평가 리포트 화면과 파이프라인 요약을 함께 배치한다.
- 흐름: 답변 transcript → NCS 역량 평가 → exact evidence → 가드레일 → 리포트 → 자동 판정·면접관 검토.
- 원칙: 가드레일 PASS 또는 REGENERATED 이후에만 최종 저장하며, 지원자 화면에는 제한된 결과만 노출한다.

### 23. 실제 시연은 5단계로 압축한다

- 목적: 별도 제출하는 시연 영상이 무엇을 증명하는지 안내한다.
- 형식: 영상 삽입 영역은 유지하되, 상단에 시연 순서를 표시한다.
- 순서: 기업 공고 설정 → 지원자 지원 → AI 면접 → 평가 리포트 → 목표 인원 합격 처리·메일 발송.
- 영상 파일은 Google Slides에 삽입하지 않고 별도 제출한다.

### 24. 팀 자체평가 초안

- 목적: 기존 양식에 맞춰 6명의 완성도 평가와 회고를 편집 가능한 초안으로 제공한다.
- 점수와 개인별 기여는 확인되지 않은 사실을 단정하지 않는다.
- 공통 문구는 역할 분담, 계약 기반 협업, 통합 과정의 어려움, 비동기·상태 전이 학습을 중심으로 작성한다.
- 개인별 점수와 구체 기여 내용은 발표팀이 최종 확정할 수 있도록 명확한 초안 상태로 둔다.

## 시각 설계

- 기존 덱의 흰 배경, 검정 제목·표 헤더, 회색 행 구분, 노란 안내 강조를 유지한다.
- 예제 워터마크와 LSTM 샘플 이미지는 모두 제거한다.
- 장표마다 하나의 주장을 제목 또는 소제목으로 전달한다.
- 화면 캡처는 프로젝트의 실제 로컬 화면을 사용하고 개인정보·토큰·이메일을 노출하지 않는다.
- 본문은 기존 템플릿 크기를 따르되, 표와 화면 설명이 겹치지 않도록 문장을 축약한다.

## 검증 기준

- 17페이지 삭제 후 페이지 번호와 25~26페이지 연결이 자연스러운지 확인한다.
- 모든 예제 문구, 예제 워터마크, 미작성 placeholder를 제거한다.
- 각 장표를 전체 크기로 확인해 텍스트 잘림, 겹침, 제목 줄바꿈을 수정한다.
- 대규모 검증 수치는 로컬 검증 결과임을 명시하고 AWS 운영 성능으로 오해되지 않게 한다.
- 개인별 자체평가는 발표팀이 확정하지 않은 기여나 점수를 사실처럼 표현하지 않는다.
- 작업 종료 전 Windows PM 로컬 하네스를 실행하고 결과를 기록한다.
